# ServicePulse — System Services Monitor

**Downloads (Windows installer, Android APK, all source zips):** https://servicepulse-downloads.pplx.app
**Live demo:** https://servicepulse-app.pplx.app

A cross-platform system monitoring app built from **one shared web codebase** (`app/`), packaged for:

| Target | Shell | Data source |
|---|---|---|
| **Windows desktop** | Electron (`electron/`) | Real CPU load, memory, and the running process list via `systeminformation` + secure IPC |
| **Android** | Capacitor (`android/`) | Device info, RAM in use, storage, and live network status via official Capacitor plugins |
| Browser (dev/preview) | any | Simulated demo data |

> Note: Electron itself does not run on Android, so the Android build uses Capacitor — the standard way to ship a web codebase as a native Android app. Both targets render the exact same UI in `app/`.

## Project layout

```
servicepulse/
├── app/                  # Shared web UI (index.html, styles.css, app.js) — platform-adaptive
├── electron/             # Windows desktop app (Electron main + preload, contextIsolation on)
│   └── app/              # synced copy of ../app (build artifact)
├── android/              # Android app (Capacitor config + generated native project)
│   ├── www/              # synced copy of ../app (build artifact)
│   └── android/          # native Android Studio project (generated by `cap add android`)
├── backend-android/      # Backend as a native Android APK (embedded HTTP server + admin console + notification access)
└── scripts/sync-web.js   # copies app/ into both build targets
```

## Features

- Live CPU load with a scrolling history chart (fast initial sampling burst, then 3s cadence)
- Memory usage meters with GB totals
- Running services table (Windows/Electron): sortable by name/PID/CPU/memory, live filter search, health status pills (healthy / elevated / critical)
- Android: device details panel (model, Android version, storage, network type), memory history chart, live network change listener
- Pause/resume live refresh
- Dark terminal-inspired theme, responsive down to phone widths, works fully offline

## Windows (Electron)

Requirements: Node.js 18+.

```bash
cd electron
npm install
npm start          # runs the app (auto-syncs the shared UI first)
```

### Build a Windows installer (.exe NSIS installer)

```bash
cd electron
npm run dist       # produces electron/dist/ServicePulse-Setup-1.0.0.exe
```

Requires Windows (or Wine) for signing/packaging; `npm start` works for development on any OS.

## Android (Capacitor)

Requirements: Android Studio (with SDK 34+) and JDK 17.

```bash
cd android
npm install                 # already done if you ran sync
npm run build               # syncs web assets + plugins, builds debug APK
```

The debug APK lands in `android/android/app/build/outputs/apk/debug/`.

Or open the project in Android Studio:

```bash
cd android
npx cap open android       # then press Run
```

### Making changes to the UI

Edit only `app/`. Then refresh both targets:

```bash
node scripts/sync-web.js               # copies app/ -> electron/app and android/www
cd android && npx cap sync android     # push web assets + plugins into the native project
```

## Security notes (Electron)

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`
- Renderer talks to the main process only through a minimal read-only bridge (`preload.js` → `ipcMain.handle`)
- Strict CSP in `index.html`; no remote code

## Discovery (mDNS)

The backend advertises itself on the local network as `_servicepulse._tcp`, so
clients find it by name instead of by IP. Records: PTR, SRV, TXT
(`v=1 api=/api/v1 name=...`) and an A record for `<hostname>.local`.

```bash
cd backend && npm start
# ServicePulse backend listening on :3210
# mDNS: advertising _servicepulse._tcp.local as "ServicePulse on studio"
```

Disable with `MDNS=0`. The first consumer is
[ALBA Companion](../alba-companion) — an Android shell that scans, resolves and
connects with zero configuration. `GET /api/v1/info` is the public handshake
used to confirm a discovered service really is ServicePulse.

## Backend (telemetry service)

`backend/` is a zero-dependency Node.js telemetry service (`npm test` runs its
suite with `node:test`). Android clients POST
snapshots to `POST /api/v1/telemetry`; a live dashboard and history API are included
(`backend/API.md` has the full reference). Optional `BACKEND_KEY` + `X-API-Key`
header protects ingestion. In the app, tap the sync gear in the top bar to configure
the backend URL — telemetry is sent every 30 seconds using the native HTTP bridge
(no CORS restrictions).

## Android app

Download `ServicePulse-debug.apk` from the
[latest release](https://github.com/redbloodfoxchaoseco-sys/servicepulse/releases/latest),
enable "Install unknown apps" for your browser, and install. The APK is signed with
the debug key; a release-signed build requires your own keystore (`android/android/`
gradle `assembleRelease`).

## Windows installer (Metro UI)

`installer/` contains an NSIS-based Windows installer with a Metro-style UI
(flat Metro-blue banner, Segoe UI, white surfaces, accent progress bar).

- **Build:** `bash installer/build.sh` (needs `makensis` + the Electron win32 zip)
- **Output:** `installer/ServicePulse-Setup-1.0.0.exe` (~111 MB, LZMA)
- Installs per-user to `%LOCALAPPDATA%\Programs\ServicePulse` — **no admin rights**
- Start-menu + desktop shortcuts, full uninstaller, Add/Remove Programs entry

### Windows requirements — nothing to install

ServicePulse is **fully self-contained**. Unlike classic .NET apps there is
**no .NET Framework (3.5 or any other version), no Visual C++ Redistributable,
and no other runtime** to install: the app bundles its own Chromium browser,
Node.js runtime and V8 engine inside the setup (the same files as the official
Electron win32 distribution). Works on any 64-bit Windows 10/11 machine.

### Android requirements — everything in the APK

The APK (`com.servicepulse.app`, ~3.7 MB) bundles the Capacitor runtime, all
plugins and the entire web UI. It runs on **Android 5.1 (API 22) or newer**,
uses only the `INTERNET` and `ACCESS_NETWORK_STATE` permissions, and renders
via the built-in Android System WebView. No Google account, no backend and no
services are required — telemetry sync is optional and configured in-app.
